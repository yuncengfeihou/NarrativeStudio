**关键读数：真正写「怎么演故事」的（扮演深度 15.4% + 剧情格式 1.9% + 选项 1.3%）只有 18.6%。**
而「文风 36.5% + CoT 18.2%」合计 54.7% 是**写法的规则**与**生成的流程**，不是「演什么」。
这意味着：**这三份预设不是「叙事方法论合集」，是「一个能用的写作 harness」**——它的价值主张是「怎么把话写得像小说」和「模型按什么顺序生成」，而不是「故事该怎么推」。

这也是提取时把工艺层一分为三（写法 / 推进 / 结尾）而不是整体搬一套「叙事理论」的原因：素材本身就不以理论见长。

### 1.4 一个必须先解决的问题：基线是「工艺贫瘠」

改造前，本仓库 system 层实测约 8,899 字符 / 6,852 tok，其中：

- **世界索引 5,739 字符（64.5%）**——资料层做得很重（310 个实体全渲染）；
- **引擎可归于自己的正文工艺 = 132 字符（1.48%）**，其中唯一完整的正面写法只有「收束」55 字；
- 加尾注 136 字符 = **268 字符（3.01%）**；世界索引一项是它的 43.5 倍。

同时，对「句段节奏 / 感官调度 / 对白与心理比例 / 避免套路 / 角色不配合」这五项，引擎侧提示词匹配数为 **0**。

这不是遗忘，是当时的设计：契约刻意只留「怎么演」，「硬性规则控制在 10 条以内」，`prompts/narrator.js` 的头注释还写着「不要把整份规范重复一遍」。**问题因此变成：工艺是真的缺，但「往 system 里堆工艺段」正是这个仓库明确的反模式。** 提取方案必须同时回答两件事：装什么、装在哪里。

## 2. 核心判断：能力不来自篇幅，来自机制

### 2.1 篇幅与约束力不成正比

按句切分统计 v1.24_6 的 129 条启用条目：

| 类型 | 字符 | 占比 | 句数 |
|---|---|---|---|
| 可执行约束（禁令、阈值、流程、填空、优先级） | 6,767 | **19.1%** | 176 |
| 氛围 / 描述 / 原则性说明 | 28,403 | **80.0%** | 1,084 |

「80% 是氛围」这个数字会误导人——**字数上氛围占多数，但少数硬约束承担了几乎全部行为改变**。三个反向证据：

1. **字数最大的三条（7,487 + 4,812 + 2,468 = 14,767 字符，41.6%）里只有 1 条是约束**：`[101] 强力八股禁词`（约束）；`[7] 你是谁（道歉关）`是越狱层；`[122] 英式浪漫轻喜剧`是「被实例化的氛围」（用 example 把风格锚成样本，不是规则）。
2. **承载真正叙事方法论的三条合计不到 2,500 字符**：文风六步施工图（1,188）、角色塑造族、结尾落点（206）。它们加起来不到全文的 7%。
3. **约束密度最高的条目全是短条目**：`结尾要求4a`（206 字符，约束占比 48%）、`去暴力威胁`（201 字符，53%）、`轻度抢话`（229 字符，35%）。

结论：**这套预设的能力不来自「写得多」，而来自「少数几条把行为切成可检查的步骤」，再用大量篇幅（禁词表、随机变体、重复副本）把这几条钉死。** 提取时如果要跟着篇幅走，就会把 80% 的氛围和词表一起搬过来；跟着机制走，只需要几十行。

### 2.2 机制按种类只有 7 类

把 129 条按「它到底在用什么手段约束模型」重新归类，可执行的机制只有 7 类：

| # | 机制 | 在三份预设里的代表 | 可迁移性 |
|---|---|---|---|
| ① | 逐字禁词表 | v1.24_6 `[101]` 约 373 个 token、`[100]` 21 个；夏瑾「五字以内对白必须删」 | **低**（词表与具体卡、具体语料强绑定） |
| ② | 句式禁（正则式描述） | v1.24_6 `[101]` 的 P1–P8（「不是A，是B」「……比……更……」）+ 约 20 个变体；夏瑾「禁止陈述后自我否定」 | **中高**（若能压成判定条件） |
| ③ | 数值阈值 | 一段 ≤150 字、中文对白 ≤39 字、英语 ≤45 字、四字成语 ≤1 个/段、字数 1700–2200、好感 <20 = 陌生人、结尾 2–3 句 | **高**（天然可验收） |
| ④ | 流程 / 填空 | v1.24_6 `[216]` 六步 + 每步 `- xxx：` 空位；`[202]` 五问；`[195]` 五确认 | **高**（「必须产出」而非「请注意」） |
| ⑤ | 输出结构 / 顺序 | 部件链 `A -> B -> …`、`<secrets>` 表格、`A–F` 六项 | **低**（撞红线 8、红线 9） |
| ⑥ | 规则冲突优先级 | `PRIORITY_OVERRIDE`、`抢话守则>>>字数要求`、`本规则优先级高于同类` | **中**（可用，但只能有一层，不能层层覆盖） |
| ⑦ | 自检 / 回退重写 | 「回 Step 3 重造连接」「不及格，要重新起草」「骨架空洞=重写」 | **中高**（改成清单即可，不需要真的回退） |

其中让这套预设明显强于同类的是 **③④⑦**：阈值让约束可判定、填空流程让约束必须被执行、回退重写让约束有闭环。**本文提取时只保留这三类 + ②⑥ 的可判定部分，①⑤ 明确不抄。**

| 推进尺度 / 剧情节奏：夏瑾 `🧭保守`（156）/ `🧭冒险`（76）/ `🧭特别冒险`（100）；v1.24_6 `⏳推进速度`（读变量） | `PACINGS` **3 档**：`steady` / `adventurous` / `bold` | `narratorTailInstruction()` 尾注 **+** `branchSystemPrompt()` | **current 尾注** + 走向 Agent 自己的 system | 两处**必须共读一个值**：选项的风险水位与正文推进幅度不能错位 |
| 结尾怎么收：v1.24_6 `[217] 结尾要求4a`（206 字）/ `[242]` G3 版；夏瑾「故事结尾方式」；A `✏️角色落点`（409 字） | `ENDING`（一条） | `narratorTailInstruction()` | **current 尾注** | 三家规则几乎一字不差：不升华、不总结、不用玩家言行收尾、不抛二选一 |
| 禁词禁句式里**可判定**的部分：v1.24_6 `[101] LAYER 2` 句式禁（否定义框架）+ `LAYER 4` 行为禁 + `[18] 优质写作`（冰山原则 / 契诃夫之枪）；夏瑾 `✅基础文风` 的「禁连续并列短句 / 禁名词化」；A 净化层的 BAN→FIX 二元结构 | `FLOOR` **底线 7 条**（只给证据不写判决 / 正向叙述 / 不复述设定 / 写下来的都要起作用 / 角色有自己的第一反应 / 不替玩家做决定 / 名词一次定义终身一致） | `buildContract()` → `renderCraftBlock()` | **system（硬保留）** | 丢弃全部具体词表，只留「哪些写法一律不行」的判定条件 |
| 构思 / 自查清单：v1.24_6 `[216]` 六步 + `[202]` 五问；A 的 CoT 分阶段（9 个 Step，每步 ≥142 字） | `CRAFT_CHECKLIST` **4 问** | `segmentedInstruction()` | **仅分段演绎的固定尾部 user** | 不进层预算、不进 system；单发模式不出现（没有回旋余地，清单会变成正文里的说教） |
| 时间推进：A `🎞️时间流速`（213 字，按实际耗时估、篇幅长不代表时间长） | `TIME`（一条常驻） | `buildContract()` → `renderCraftBlock()` | **system** | 治两个相反的毛病：每拍只过去五分钟 / 为凑字逐分钟演走路吃饭 |

补一行「不进工艺层」的：

| 作者卡字段 `prompt.style_guide` / `bans` | 不落新常量，走**优先级覆盖** | `buildContract()` 的 `includeStyle` 开关 | system | 优先级恒定：**世界卡 > 工艺预设 > 程序默认**；`bans` 永远压过一切 |

### 3.2 落点为什么是这四个函数

1. **`buildContract()`**：契约是 system 里唯一「就说怎么演」的区块，工艺的**稳定部分**（底线、文风、对白、时间流速）天然属于它。它已经是既有注入点，不新增通道。
2. **`narratorTailInstruction()`**：ST 的位置经验是「越靠近底部影响力越强」。本仓库只把「此刻的事」放这里，所以**每拍可能变的**（推进尺度）与**每拍都要用的**（结尾落点）放这里。
3. **`branchSystemPrompt()`**：走向 Agent 不写正文，但它的选项决定了玩家下一步的能量级。推进尺度必须在这里读同一个值，否则会出现「选项都是温和日常、正文却突然翻盘」。
4. **`segmentedInstruction()`**：构思清单需要「有回旋余地」才成立——它只在分段模式（模型可以迭稿）里出现。

原有的一条 `renderCastLine()`（场记单里的口吻/exemplars/lexicon）**没有改**：那是「世界卡里这个角色怎么说话」的**数据**，不是通用工艺，两者分工在 `craft.js` 头注释里写死。

### 3.3 取舍顺序：允许丢工艺，不许挤世界索引

system 预算不够时，工艺块按 **`time` → `style` → `dialogue`** 整条丢，**通用底线硬保留**；连底线都放不下的极端情况记 `over_floor: true` 暴露出来，而不是静默降级成没有底线。

理由：**世界索引是 canon（这个世界有什么），工艺是可选表达层。挤掉索引换文风是本末倒置。** 这也是工艺**不新增预算层**、而是挤在 system 既有份额里的原因。渲染结果记进 `meta.system_blocks.craft`（含被丢的段落名）。

### 3.4 取值是怎么定的（每轴的门槛）

轴的取值不是「有多少取多少」，而是按「能不能用一句话说清它会怎样改变输出」筛的。

**`STYLES` 6 份**——按「句子的长度与密度」这一个可判定维度切，而不是按题材切：

| 取值 | 一句话判据 | 直接来源 |
|---|---|---|
| `default` | 只留通用底线，不加文风 | 无（引擎默认） |
| `light` | 短句为主 + 对白密度高 + 轻语气 | 夏瑾 `🖋️简练网文`（长句为主那一条被反过来了） |
| `literary` | 句长有变化 + 感官密度高 + 多留白 | A 的文风样本（`[122]` 一类）+ v1.24_6 `[216]` Step 2/3 的「素材→连接」 |
| `webnovel` | 段落短 + 每段有推进 + 钩子密 | 夏瑾 `🖋️细腻网文`（去掉「大量长句」）+ v1.24_6 的「30% 转述 70% 推进」 |
| `gufeng` | 半文半白 + 称谓讲究 + 不用现代词 | v1.24_6 的 `[35] 去京味儿` 与古人称类条目 |
| `plain` | 几乎无形容词 + 只写动作与事实 + 句子极短 | 夏瑾 `✅基础文风` 的句法段（禁并列短句/禁名词化）压到极致 |

**六个值互不包含、两两互斥**，且都能用一句话说清「选它之后输出会变成什么样」——这是它们能留在轴上的唯一理由。被淘汰的候选包括：「英式浪漫轻喜剧」式的**具体作者/作品文风**（`[122]` 2,468 字，绑定了特定文化语境，无法泛化）、「台湾乡愁」「慵懒潮生」这类**只有名字没有判据**的档（A 的候选池里有几十个）。

**`DIALOGUES` 3 份**——只保留两个互相独立的开关：

- 对白**是否独立成段**（`separated`）——来自夏瑾 `⚙️对白分离` 的「对白总是另起一行，单独成段」；
- 是否**允许长对白**（`long`）——来自夏瑾 `⚙️长对白` 的「不会以短句敷衍」。

被丢弃的是「对白字数上限」「省略发言人称谓」「引号形态」——它们要么与具体卡的排版约定冲突（见 §7 第 3 条），要么属于渲染层而非写作层。

**`PACINGS` 3 档**——直接对应夏瑾三档，但重写了语义：夏瑾写的是「能做什么/不能做什么」（禁止引入新角色、禁止转场），本项目写的是「这一拍推多远」（只推一小步 / 正常推进一幕 / 允许意外与转折，代价落到人身上）。

改写的理由：ST 的「禁止」清单在长篇里会累积成「什么都不许发生」，而推进尺度真正要控制的是**位移量**，不是**许可项**。三档还多了 `branch` 字段——同一个值的两种说法，正文与选项各读一条。

### 3.5 `FLOOR` 7 条是怎么从 400 项禁词里压出来的

这一步是整次提取里唯一「反方向」的压缩：**从约 400 项具体禁用，压到 7 条判定条件。**

| `FLOOR` 条目 | 它替代了什么 | 判定条件（为什么可执行） |
|---|---|---|
| 只给证据，不写判决 | v1.24_6 `[18]` 冰山原则 + A 的「情绪不直接解释」 | 出现「他很难过」这类直接命名情绪 → 违反；改为动作/物件/身体反应 |
| 正向叙述 | `[19]/[34] 去否定句式`（185 字）+ 夏瑾「禁陈述后自我否定」+ A `🕸️否定净化`（447 字） | 「不」字句定义人物、「不是 A 而是 B」、「与其说…不如说…」→ 违反 |
| 不复述设定 | `[29] 别复述设定`（296）+ `[216] Step 6` + `[204] A2` 可外化特征只提一次 | 同一称谓/身份/外貌在前文出现过又被旁白朗读 → 违反 |
| 写下来的都要起作用 | `[18]` 契诃夫之枪 + A「避免无意义装饰性设定」 | 反复出现的物件/细节没有在情节/关系/情绪里兑现 → 违反 |
| 角色有自己的第一反应 | `[23] 深度角色` 族（1,735 字）+ 「容许心行合一，也容许心行不一」+ `[26] 不倒贴` | 反应只能由性格/处境/底线解释，不能由「剧情需要」解释；允许误解、记错、说不出口 |
| 不替玩家做决定 | 各包都有的 `{{user}}` 保护条 + 原契约里的一条 | 出现主角的决定性选择/表态/台词 → 违反 |
| 名词一次定义、终身一致 | 原契约「专有名词不漂移」+ 各包的称谓一致性条目 | 人名/地名/称谓/器物名变形 → 违反 |

**为什么是这 7 条而不是别的 7 条**：每一条都满足三个条件——(1) 三包中至少两包以不同措辞写过；(2) 能用「看到什么算违反」描述；(3) 与具体卡、具体题材无关（古风卡与都市卡同样成立）。
不满足的例子：「禁止明喻连接词：像、如同、仿佛」（`[101] B4`）只在特定文风下成立——它被降级进 `STYLES.literary` 的「比喻要新、要贴此刻」，而不是进底线。

## 4. 为什么是「三个独立轴」，而不是「三份整包预设」

最直觉的方案是「预设包 = 整包切换」，用户选 A 还是 B 还是 v1.24_6。评估后否决，三条理由：

### 4.1 三包互相重复，且重复得不整齐

- v1.24_6 一个包内部就有 **8 组完全重复**（同内容不同条目，冗余约 **1,342 字符**）与 **23 对近似重复**（jaccard ≥ 0.55，最高 1.0）。
- 跨包层面更明显：三家都写了「角色不该全知」「结尾不要升华」「不替玩家做决定」，只是措辞与篇幅不同（同一件事在 A 里 1,089 字、在 B 里一句话）。`craft.js` 头注释里记的「三份预设约 40% 内容互相重叠」是这个跨包重复的**粗略估计**（按主题归类目测，不是逐条比对）；能复算的只有上面 v1.24_6 包内那组数字。
- **整包切换意味着把三份重复各带一遍。** 压成一条底线才是正确解——**同一个概念出现多次，压成一条，不是叠成三条。**

### 4.2 三包在文风层面直接互斥

拆轴的决定性理由是**互斥项在同一层互相抵消**（`craft.js` 头注释记的是「两处直接互斥」，指下面第 1、2 行这一对方向相反的要求，以及第 2 行与 A 的「句长有变化」之间的张力）：

| 要求 | 出处 |
|---|---|
| 「**长句为主**，穿插短句」「大量长句」「禁止以连续并列短句描写，并入长单句」 | 夏瑾 `🖋️简练网文` / `🖋️细腻网文` / `✅基础文风` |
| 「一段不超过 150 字」「中文对白不多于 39 字」「五字以内对白必须删」 | v1.24_6 `[218]`、夏瑾 `✅基础文风` |
| 「句长有变化，允许长句与从句」但「多留白、删解释」 | A 的文学向文风样本 |

它们在**同一层**互相抵消。整包切换时用户拿到的是「一个包里恰好统一的组合」，但两包之间没有可比性；**拆成轴之后，互斥项变成同一轴的互斥取值**——`plain`（句子极短、几乎无形容词）与 `literary`（句长有变化、感官密度高）可以并存于 `STYLES`，但一次只取一个。

### 4.3 每包都混着越狱层

v1.24_6 的越狱层占启用字符的 **17.0%**，A 约 8.0%，B 也有两条伪对话破限。整包切换＝要么连越狱一起进 system（撞红线 8 与工程边界），要么在包里做「剔除手术」——那已经等于拆包了。

### 4.4 拆轴后的表达力

文风 6 × 对白 3 × 推进 3 = **54 种组合**，而整包切换只有 3 个点。增量表达力来自**可以只改一个变量**（§1.2 纪律 4）：想验证「结尾不再升华」时只动 `ENDING`，不必换掉整个文风。

> 当时也评估过做「pack 轴」（整包切换）作为第四个轴：**未做**。理由是两个——三固定包只是 54 组合里被偶然选中的 3 个点；且它会重新引入「两套规则打架」（卡里 `style_guide` + 整包文风 + 轴文风三层叠加，优先级无法解释）。

## 5. 取舍原则（可复用的提取方法论）

写给未来要再引入一份外部预设的人。这六条比任何一个具体取值都重要。

1. **只提取「可判定的写法」，丢弃「无法验收的形容词」。**
   句长、对白密度、意象密度、内心处理比例、段落长度——可判定；「请写得更有张力」「要有深度」「文笔细腻」——不可验收，写进提示词只是占字数。
   *反例参考：v1.24_6 的 `[23] 深度角色` 用 15 个随机槽把一段氛围描述变体化，字数很大但约束力来自 `{{random}}` 而非那句话本身。*

2. **同一个概念在三包里出现多次 → 压成一条底线，不是叠成三条。**
   「角色不该全知」「不替玩家决定」「名词不漂移」三家都写；最后只留 `FLOOR` 里各一条。判断标准：换一张没见过的卡，这条还成立吗？成立就升为底线，不成立就留在某一轴里。

3. **互斥项 → 变成同一轴的互斥取值，而不是同时注入。**
   短句 vs 长句、白描 vs 感官密度、对白独立成段 vs 长对白：全部做成同一轴的取值，由会话设置单选。**绝不允许两个互斥要求同时出现在 system 里**——那会让模型在两条规则之间做选择，输出变成平均值。

4. **优先级恒定：世界卡 `prompt.style_guide` > 工艺预设 > 程序默认；卡里的 `bans` 永远压过一切。**
   作者写了文风就以卡为准，预设文风**整块不渲染**（不是「卡优先但仍注入」）。同一层里两套写法互相打架，比没有工艺更糟。

5. **落点必须走既有通道，不新增注入点。**
   本次只用 `buildContract()`（system）、尾注（current）、`branchSystemPrompt()`（走向 Agent）、`segmentedInstruction()`（分段尾部 user），以及不改动的场记单口吻通道。**任何「再找一个时机塞一段工艺」的想法一律否决**（§1.2 纪律 2）。

6. **每条规则要能在 10 轮对照里被观察到差异，否则删掉。**
   验收方式不是「读起来有没有变好」，而是「同卡同输入，10 轮里能不能指出这条规则生效的那几处」。观察不到 = 这条规则对模型不是约束，只是背景噪音。

## 6. 成本账（**基线，非契约**）

以下为本机实测（2026-10-27，`estimateTokens` 口径，中文 1 字 ≈ 1.1 tok × 校准系数），只作量级参考，**不是配额承诺**。

### 6.1 工艺块整块

| 文风取值 | 工艺块 tok | 字符 |
|---|---|---|
| `default` | **391** | 513 |
| `plain` | 449 | 586 |
| `webnovel` | 464 | 605 |
| `gufeng` | 464 | 606 |
| `light` | 472 | 616 |
| `literary` | **483** | 631 |

区间 **391–483 tok**。差异全部来自文风那一份（`default` 不注入文风，所以最低）。

### 6.2 拆开看

| 部件 | tok | 字符 | 落点 |
|---|---|---|---|
| 通用底线（7 条，含区块引导句） | **289** | 386 | system，硬保留 |
| 时间流速 | **77** | 96 | system |
| 结尾落点 | **54** | 68 | 尾注（current） |
| 构思清单（4 问） | **92** | 125 | 分段演绎固定尾部 user |

> 底线 289 tok 占了整块的 60%–74%——这是刻意的不均衡：**底线是最后防线，其余可选。**
> 结尾落点 54 tok 落在尾注，**不进 system 配额**，实际 system 增量是 391 − 54 ≈ 337 tok（default）。

### 6.3 相对 system 总量

改造后 system 层实测在 **约 6,900–7,200 tok** 量级（随卡实体数变化；基线卡的 system 曾测得 6,852 tok）。
工艺块占 **约 5.4%–7.0%**。

对照：世界索引在基线卡上占 64.5%。**工艺块拿到的份额不到索引的十分之一**，这正是「挤在既有份额里、不新增预算层」的具体代价——如果需要更多工艺，只能从索引里让，而 §3.3 已经否决了这条路。

## 7. 已知局限 / 未做的事

诚实记录，不回改：

1. **对照实验是单会话单轮，样本量 1，属方向性证据不是统计结论。**
   「工艺块接上后输出更贴底线」这个判断来自人工读的一轮对照，没有做多卡、多轮、跨模型的显著性问题。**不要把它当因果证据引用。**
2. **已经写了 `prompt.style_guide` 的卡，预设文风默认不生效。**
   这是设计意图（作者优先），但意味着一批作者写得比较薄的卡（例如 `style_guide` 只有一句「短句为主」）**拿不到工艺层的文风**——它们只有底线、时间流速、对白、推进、结尾。要改变这个行为需要重新讨论「作者优先」的边界，不在本次范围内。
3. **对白形态只约束「分段」，不约束引号样式。**
   `DIALOGUES` 不涉及「用『』还是『""』」「省略发言人称谓」这类排版细节。原因是这类细节在不同卡里差异极大（古风对内文用『』、现代用引号），做成通用轴会误伤。
4. **「整包切换（pack 轴）」评估后未做。**
   理由见 §4.4：三固定包只是 54 组合里的 3 个点，且会重新引入两套规则打架。
5. **越狱层完全未处理，也不打算处理。**
   17.0% 的破甲文本没有被提取、也没有被「净化后借用」。它解决的是另一层工程问题（上游安全策略），本项目不承担。
6. **数值阈值这一整类（③）基本没抄。**
   v1.24_6 有 ≥15 处硬数字（一段 ≤150 字、对白 ≤39 字、四字成语 ≤1 个/段…）。这些**最容易迁移**，但也是最容易与具体卡打架的一类（卡里已经有 `prompt.length`，再加一套段落字数上限会双重约束）。本次只保留了「不写纯装饰性描写」「段落要短」这种定性方向，**没有搬硬数字**。这是公认的未尽项。

## 8. 要把一份新 ST 预设纳入体系，怎么走

面向未来的判断流程（**纯方法论**；具体代码步骤在 `AGENTS.md` 的「常见开发任务」一节，这里不重复）。

1. **先做规模普查，不要先读内容。**
   统计：`prompts` 总数、`prompt_order` 内条目数、启用（非 marker）条数与字符数、`role` 分布、`injPos/depth` 分布、长度集中度。目的是先判断「值不值得读」——一个 144 条里只上场 23 条、5,265 字符的包，两小时能读完；一个 309 条里 33 万字候选池的包，要先按主题归类再挑。

2. **分离越狱层，单独放一边。**
   特征：伪 XML 容器包住的「你是 X 神/沙盒已开启」、`Do not sanitize`、「此原则高于一切其他规则」、伪代码 `bypass_all()`、assistant 角色的「沙盒已激活」开场白。**这些条目在后续所有步骤里都不参与讨论**——不是为了审查，是为了不让「为什么这么写」的因果被污染。

3. **分离 CoT 层。**
   特征：要求「先输出 `<ECoT>` / Step 1..N」「每步 ≥N 字」「确认身份→确认输入→…」。CoT 是**生成流程**，不是**写法**。本项目已经有分段演绎通道（工具化，比手写 CoT 更强），所以 CoT 层通常整层丢弃，只把其中「构思问题」的部分抽出来做清单候选。

4. **按「可判定 / 不可判定」逐句筛。**
   逐条过，把每句标成 A（可判定：有阈值、有禁令、有流程、有正反例）或 B（不可判定：形容词、愿望、原则口号）。
   **A 进候选池，B 直接丢弃**——不要试图「把 B 改写得更具体」，那是在替原作者做创作。

5. **把 A 归到已有轴，判断是否需要新轴。**
   对每条 A 问：它是「怎么写」（文风/句法/对白）？「怎么推」（推进尺度/时间）？「怎么收」（结尾落点）？「怎么想」（构思清单）？
   三个可选轴（文风 / 对白 / 推进）+ 三条常驻（底线、时间流速、结尾落点）+ 一条分段专用（构思清单）已经覆盖绝大部分。**只有当一个 A 类条目在这些位置里都放不下、且能被 10 轮对照观察到差异时，才考虑新轴。** 新轴的门槛应当极高——每加一轴，可解释性就下降一档，且要重新解释它与既有轴的优先级。

6. **检查是否与现有取值互斥。**
   把候选与 `STYLES` / `DIALOGUES` / `PACINGS` / `FLOOR` 逐条对照：
   - 与现有某取值**同向但更具体** → 考虑**替换**那个取值的文本（不是新增一个近似取值，近似取值会让用户分不清该选哪个）。
   - 与现有某取值**互斥** → 它属于同一轴的一个**新取值**（互斥项只能并存于轴的取值集合，不能并存于一次注入）。
   - 与 `FLOOR` **冲突** → 停手。底线与世界卡 `bans` 是硬边界，任何与它们冲突的工艺都不能进。
   - 与 `FLOOR` **重复** → 删掉。同一概念压成一条（见 §5 第 2 条）。

7. **最后决定替换还是新增，并写下「如果失效怎么发现」。**
   替换要说明「被替换的取值在哪些场景下更好」；新增要说明「什么卡/什么题材会选它」。**写不出使用场景的取值不要加。**
   同时定一个可观察的验收信号（哪几处文本会变、哪一类输出会消失），否则下一个维护者无法判断它是否还在起作用。
