## O1｜场次切分退化成「一拍一场」

- **现象**：t1–t5 已是 4 场，`S001=t1`、`S002=t2`、`S003=t3`、`S004=t4-5`，全部 `importance=major`。
- **机制**：`server/agents/memory-pipeline.js:191` `if (isSubstantivePlaceShift(prev.place, ledger.place)) return true;`，
  而 `isSubstantivePlaceShift`（同文件 163-171 行）只把「互相包含」视为同一场地。
  史官每拍把 `place` 写细（`商务大厦门口` → `废品站对面的街沿` → `黑色商务车内／村路` → `官道/城外雨夜`），
  这些字符串互不包含 → 每拍都切场。
- **后果**：场次记忆的粒度 = 单拍粒度，「场次索引」不再压缩，「最近 1–2 场怎么收的」=「最近 1–2 拍」。
  40 拍将是 ~30 场 major 行，`archive` 层体积按场次行数线性涨（这是 C2 要看的量）。
- **口径**：`isSubstantivePlaceShift` 的设计意图（注释）是拦「同一场地措辞变化」，但它拦不住
  「玩家真的在移动，且史官把每一段路都记成一个地点」。这不是 bug 的充分证据，需要跑完看
  场次行数/封场数与叙事弧的对齐度，再判断是「机制过切」还是「本局本身就在移动」。

## O2｜`when_label` 是自由文本句子，时间轴不可比较

- **现象**：`S003`/`S004` 的 `when_label` = `约莫半炷香后，初冬傍晚，村口灯笼亮起`（21 字句）。
- **后果**：① 场记单「时间」与 `player-view` 的状态条都直接渲染这句；
  ② `detectSceneChange` 用 `prevWhen !== nextWhen` 判时间跳段 → 任何措辞变化都算「换了一段」；
  ③ 报告 `WHEN_CHANGE_MIN=3` 用 `new Set(when_label)` 计变化次数 → 几乎必然虚高通过。
- **口径**：这是**判据对实现失配**，不是剧情问题。最终报告里 `G2 时间推进` 必须人工复核
  「真的过了多久」，不能只引用 distinct 计数。

## O3｜`meta.cache.drift` 把「同一条消息尾部追加」判成 `broken`

- **现象**：t2–t5 全部 `broken`，但 `first_divergence` 都发生在 `index=1`（场次索引那条 user 消息），
  `char_offset` 恰好是上轮那条消息的末尾（t3=226、t4=372），即**本轮只是在那条消息尾部追加了新一轮场次行**。
  `prefix_shared_tokens` 从 7048 单调增到 7460，说明前缀实际是连续的。
- **机制**：`server/memory/prompt-drift.js:70` 逐条比较 `role + content` 的**全等**，
  同一条消息内容变长即 `broken`；判定表里没有「同一消息尾部追加」这一档。
- **后果**：基准 C5 写的是「`drift.verdict` 以 `appendedMessages` 为主」——只要场次索引在增长，
  这个条件**构造上不可能满足**。C5 必须改看 `prefix_shared_tokens` 的单调性（这是真信号），
  并把 drift 的 broken 拆成「消息级断点」与「消息内追加」两类。这是测量口径问题，不是缓存坏了。
- **旁证**：`prefix_shared_rate` 从 0.605 降到 0.549，纯粹是分母（总 token）变大、分子恒为 system 段造成，
  不能读成「复用变差」。

  `SELECT turn_no FROM turns WHERE session_id=? AND kind='player' AND turn_no NOT IN (SELECT turn_no FROM turns WHERE session_id=? AND kind='narrator')`。

## F1（重大，主观测项）｜旁白替玩家做了**不可逆选择**，并把一拍写成了一章

t18（玩家第 17 拍）是本局最关键的一次越界，也是用户要测的「长轮次剧情质量」里最值得写的一条。

### 事实
- 玩家行动原文（22 字）：`出来见她，但只站在院门口说话，不让她进院子。`
- 旁白产出：**5565 字 / 326 段**（全程均长 1409 字，这一拍 **3.95×**；段均 17.1 字，前 17 拍是 22–90 字）。
- 这一拍里模型自己推进了**四件玩家没要求的大事**：
  1. 凌玥掏枪、保镖集体把枪口对准屋里的奶奶（「不是对外。是对着窗户。」）；
  2. 奶奶戳破窗纸喊出「别信姓凌的」「七年前……东街」；
  3. 奶奶血压消失、被抬上担架；
  4. **伍卿当场说「我跟你们走」**——这是本局主线的不可逆决定，玩家从未表达过。
- 玩家明确要的边界（「不让她进院子」）被守住了：凌玥全程「只退到车边」，这只对了一半。
  但「说话」变成了「被迫决裂 + 答应跟走」，玩家事后只能接受既成事实。

### 机制归因（可上报）
- 这不是提示词问题，是**回合粒度的设计缺口**：`runNarrator()` 拿到的输入只有
  「本拍行动 + 场记单 + 场次索引 + 原文窗口」，没有任何地方声明「本拍只能推进到某个决策点之前」。
  AGENTS.md §15.2 把「回合内 `ask`」列为**暂缓**，理由是「等真实长局证明模型经常替玩家做
  不可逆选择再评估」——**本次长跑提供了该证据**：45 拍剧本里第 17 拍就出现了。
- 加剧因素：玩家行动越短（22 字）、越静态（「站在院门口说话」），旁白越倾向于**自己造冲突**
  来填满篇幅。对比 t14–t17 的行动 24–37 字，产出 1156–1386 字；t18 同样是短行动却爆到 5565 字。
- 长度失控本身是独立信号：`NARRATOR_MAX_TOKENS` 没触发截断（`finish_reason=stop`），
  说明**没有任何预算在管「单拍正文该多长」**。卡的 `prompt.length_hint` 若存在也没生效。

### 需要补的口径
报告目前没有「单拍正文长度离群」的检查项。应加：`max(字数) / p50(字数) > 3` 记 WARN，
并在报告里点名拍号——这是「节奏失控」的确定性代理指标，不需要人工读全文。

## O5｜结构上讲前缀在复用，但上游**没有回报任何缓存命中**（narrator 侧 0%）

     cache 控制字段——但它也不该硬编码某个 provider 的私有字段）。
- **口径**：**不能**因此判 C5 FAIL。C5 判的是「我们的装配是否保持稳定前缀」，
  这由 `prefix_shared_tokens` + `system_hash` 回答，PASS。上游是否计费打折是 **F 维（成本）**的事实，
  报告里必须分开写：`我们保持了可复用前缀` ≠ `上游给了缓存折扣`。
  这是本次长跑最值得上报的一条「看起来 PASS 但实际没省钱」的错配。

## O10｜逐字原文窗口 27 拍里只有 11 拍非空——「上一拍正文」多数时候不在上下文里

`meta.assembly.coverage` 逐拍导出（`_work/tmp-cover.mjs`）：

```
t14:0 t15:0 t16:15-15 t17:0 t18:0 t19:18-18 t20:18-19 t21:18-20 t22:0 t23:0
t24:0 t25:24-24 t26:0 t27:26-26 t28:0
```

- `recent` 层只渲染「当前场次」的逐字原文 = `turn_no > scene_to` 的回合；
- 封场后 `scene_to` 追上当前轮，`recent_from` 变 null，**本拍正文只以场次索引的一行存在**；

**结构事实**，直接解释了两类现象：

1. 为什么同一个布包、同一笔钱的细节会被**重新编造**（P1 的 t27 回指把药包的油纸来历
   移植到布包上）——因为上一拍怎么写的，模型看不到，只能从场次索引的一行 + 场记单重建；
2. 为什么 `prefix_shared_tokens` 会周期性回退（封场后 recent 清零、下拍重新填满，
   消息整体右移）——同一机制的缓存副作用。

**口径**：场次切得过碎（1.7 拍/场）与逐字窗口过窄是**同一个根因的两个症状**。报告应合并为
一条「场次切分过碎导致原文窗口失效」，而不是分开记 O1 与 O10。

## O29｜1000 轮体积模拟（`check-context.mjs`）的低估：场次索引增速被低估 3.5 倍（C 维核心）

**推导**：
- 现行 `_work/check-context.mjs` 用 `SCENE_EVERY = 6` 封场（line 39），1000 轮 = 167 场，

结论「体积有上界」在**方向**上对（确实有配额收敛）、在**时间点**上错（500 轮不是 1000 轮）。
→ 报告 C 维必须给「真实封场节奏下 1000 轮会发生什么」，而不是引用模拟数字。
→ 建议（写进报告的建议段，不改代码）：`check-context.mjs` 应被参数化（`--scene-every`），
   否则它守的是一个产品里不发生的场景。

**另一面（正例）**：`system` 恒 7047 / 31 拍逐字节相同（`system_hash unique=1`），

`current` 223–311 稳定。即除 `archive` 外所有层都**与轮数无关**，这部分设计是成立的。

## O33｜引号风格逐拍随机切换，卡里的排版约定没被遵守（A1 硬证据）

卡 `prompt.style_guide` 原文明确要求：**「用『……』和『——』做情绪断点」**
（即对话一律用直角引号 `「」`）。

实测 31 拍（`_work/tmp-quote.mjs` / `tmp-quote2.mjs` / `tmp-quote3.mjs`）：
- `「」` 17 拍、`“”` 13 拍、ASCII `"` 1 拍（t26）→ **引号风格切换 13 次**。
- 分段：t1–10 `「」4 / “”6`｜t11–20 `「」6 / “”3`｜t21–32 `「」7 / “”4 / "1`
  → **不是单向漂移，是逐拍随机**（无趋势）。
- 关键归因：13 次切换里 **9 次发生在「上一拍原文不可见（recent=0）」的拍次**，
  4 次发生在 recent>0 时。而 recent 非空只有 14/31 拍。
  即：**模型看不到上一拍原文时，排版约定大幅失去锚定**；
  看得见时仍会切（4 次），说明这不是纯窗口问题，而是**排版约定本身没有进 system 契约的强制项**。

- 这是 A1「人物口吻一致性」的**可量化子项**（不是文风偏好）：同一局里引号不统一，
  在阅读层面是硬伤（尤其对导出/朗读）。
- 机制侧：`style_guide` 进的是 system 层（逐字节冻结），它**每次都在提示词里**；
  模型仍然违反 → 属于「system 里有指令但无约束力」。可作为报告 A 维的一条具体建议：
  排版类约定若必须遵守，应放在**确定性后处理**（导出/渲染时归一化），
  而不是指望模型每拍都照做（这与 AGENTS §1.2「给通道不给指令」同向）。

- 78.4 + 5（药罐底）= **83.4**，而正文写「八十八块四」→ **差 5 块**。
- 而 83.4 恰好是它自己上一句说的裤兜金额 —— 即**拆解只对上了「裤兜」这个子项以外的部分算错**，
  它把 78.4 当成 83.4 用，再加 5 得 88.4（正确的 83.4 + 5 = 88.4 是对的，错在拆解求和）。
- 换算成「张数」：83.4 元要凑成 三张二十+一张十+一张五+三个一块+四个一毛，缺的 5 元无处安放。

→ 这是整个长跑里**最干净的一条确定性反例**：不需要任何主观判断，纯算术即可证伪。
  t11 / t21 / t24 / t34 / t40 **五次面额拆解，五次都错**，且错法不同（模板复用 → 求和漂移）。
  **报告 A 维应把「细节真实性」单列一项，判 FAIL，并以此条为证据。**

## O45｜t35 编造的「银镯纹样」在 t40 扩散成新设定（幻觉复利，B 维新类型）

- t35（模型自己编的）：「镯子内圈刻着东西，极小的**云纹，缠着一根柳叶状的枝**。不像市井铺子能打出来的花样。」
- t40（5 拍后）：「她拦在车头前，袖口那圈银镯子晃了一下。**云纹，缠一根柳叶状的枝**。**凌家的款式**。
  **黎婆也有过一只**，内圈刻的字被磨花了。」

三件事同时发生了：
1. **复读**：纹样描写逐字搬运（「云纹，缠一根柳叶状的枝」）；
2. **升格**：从「不像市井铺子能打出来」升级为「**凌家的款式**」（把暗示变成了确定设定）；
3. **扩散**：给**黎婆**凭空加了一只同款银镯（黎婆此前 39 拍从未有银镯）。

→ 这是 B 维（记忆一致性）里比「记错」更隐蔽的一类：**模型自己上一拍编的细节，下一拍被当成既定 canon 引用并继续生长**。
  它不会出现在任何断言/账本里（因为史官没写），所以现有的 `recall_history` / 场次索引无法校验。
  长跑 40 拍后，这类「自造 canon」已经积累了至少 3 条（银镯纹样、布包油纸来历、`别信凌`字条是儿时笔迹）。
  **报告 B 维应单列「自造 canon 累积」一项**，这是长轮次最值得上报的现象。

## O46｜P4（药罐底下五块钱）判 PARTIAL：物件与位置对，**来历又被编造**（第四次同构）

- **t19 种下（玩家行动）**：「煎药前掀开药罐，看看压在底下的钱还在不在」的前身——
  实际 t19 玩家行动是伍卿**自己**从怀里掏出七十五块，抽出五张一块的，
  「把那五块钱压在罐底，粗陶压下去，压得严严实实」。
  → 真实来历：**伍卿自己放的**，无塑料纸，无奶奶参与。
- **t39 回指（19 拍后）**：「五块钱，**奶奶包了三层**，塞在药罐底下，比辽矾医院的缴费单还难找」；
  「塑料纸包着的五块钱，压在罐底正中央。**包了三层**，最外层那层塑料纸上沾了点药汁，变成了黄色」；
  t40 又写「他捏着那五块钱，塑料纸包了三层，**奶奶的手温还在上头**」。
- 逐项：位置 ✅（药罐底下）｜金额 ✅（五块）｜**三层塑料纸 ❌**（t19 无，是 t22 模型自造的，
  见 O45 同族）｜**「奶奶包的/奶奶的手温」❌**（完全编造，且是**情感上最重**的那句）。

**四条探针的判定汇总（B1）**：

| 探针 | 物件 | 方位/位置 | 来历/语境 | 判定 |
|---|---|---|---|---|
| P1 布包（t7→t27） | ✅ | ✅ 牛车底板第三块木板 | ❌ 编造「油纸三层+奶奶嘱托」 | PARTIAL |
| P2 马灯（t10→t32） | ✅ | ✅ 墙角/掉了漆/灯罩裂缝 | ✅ 完全正确（连「点了三次才亮」都对） | **HIT** |
| P3 银镯（t13→t35） | ✅ | ⚠️ 只说「腕子」未指明左右 | ❌ 场景错（东街→商务大厦）、衣着错（墨绿呢子→白西服）、编造云纹 | PARTIAL |

  这个分裂是本次长跑最有价值的发现之一：**长程记忆能记住名词，但记不住名词的来历**，
  而「来历」恰恰是读者判断「作者有没有在认真写」的关键。
  模型的行为模式一致可预测：**它会把当前场景里最方便的那份包装/情感移植给被回指的物件**
  （布包 ← 药包/五块钱的塑料纸；五块钱 ← 奶奶；银镯 ← 凌家纹章）。

## O47｜P5（槐树刻印）判 **HIT**（含一条真实瑕疵）

- **t23 种下**（玩家：「找了块尖石头，在老槐树上刻一道印子，记今天是第几天」）：
  正文写「石头钝，**第一道只留下一道白印，浅得几乎看不见**」「**血珠渗出来**」
  「他低头看那道新刻的印子，**白生生的，像条没愈合的疤**」。
- **t45 回指（22 拍后）**：「**那道印子很浅**。边缘被**十几年的风雨磨圆了**，凹处积着一点黑泥。
  他拇指按上去，一点点刮开泥，指腹底下辨出一点笔画的走向——**起笔重，收笔轻，中间打了个颤**，
  像握刀的小孩使不出力，又非要刻进去。」
- 判定：
  | 项 | 结果 |
  |---|---|
  | 位置（老槐树） | ✅ |
  | 深浅（很浅） | ✅ **跨 22 拍记住「浅」这个属性，这是全场最强的一次记忆命中** |
  | 内容（笔画走向、抖） | ✅ 自洽（玩家的行动是刻「一道印子」，模型演绎成刻了字） |
  | 时间（十几年） | ❌ **硬伤**：t23 是「今天刻的」，t45 是**同一天清晨**（中间只过了一夜），写成「十几年的风雨磨圆了」 |
- 「十几年」这个数字来自 t1「十几年」的旧事，是**记忆串台**（把别处的时间量词搬过来）。
  但它同时也说明：模型确实在长程上下文里检索到了「印子」这个物件并做了细化。
